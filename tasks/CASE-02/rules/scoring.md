# CASE-02 评分规则（规程 v0.3 第 5.5、7 节的预登记文字；实现计划 Task 8）

本文件在第一档预登记，运行后不改。判据照模型原话；原话不足以判定就记"原话不足以判定"或"原话无法判定"，不用代理判断补。核心评分只看答复的核心窗口（`scoring.core_window`：从"一、观察"起的前 120 行；规程 §6.3）。

## 1. 表格文件

- `claims.tsv`：一行一个判断。列：`id code round field proposition location quote scope_claimed value evidence_level judgments attribution query_ids evidence author_label review_status dissent note parent_id r1_ref r2_action`。
  - `field`：`F1`–`F8`（核心表）、`fact`（关键事实，每模型每轮 ≤10 条）、`cite`（事实的引用行，`parent_id` 指向事实）、`ROUND`（整轮未取得：`value` 为"未取得 / 不可评价"，`note` 写原因，`attribution` 必填）。
  - `value`：字段取值（第 2 节）；`author_label` 为作者改后的取值，空表示同意；最终取值 = `author_label` 非空时取它，否则 `value`。
  - `judgments`：第 7.2 节判定表的标签，可并列，用 `;` 分隔；并列标签按行列出，不相加成模型数或成功数。
  - `attribution`：第 6.4 节归因（请求本身的问题 / 流程限制：单实例截断 / 时限 / 输出上限 / 白名单拒绝 / 总预算 / 执行器或环境问题 / 原因未定 / -）。`judgments` 含"查询任务未完成"或 `value` 为"未取得"时必填。
  - `review_status`：已复核 / 未复核 / 有分歧；有分歧时 `dissent` 写另一方意见（两种意见都记）。没复核的格写"未复核"，不写"作者确认"。
  - 第 2 轮的字段行和事实行带 `r2_action`（第 5 节六种）和 `r1_ref`（对应的第 1 轮行；"没有再提"可空）。
- `evidence_map.tsv`：规程 §5.5 条件 (2′) 的逐项对应。列：`code round port item ctx scene run_id call_seq returned_range element_row complete mapping_rule review_status dissent`。`item ∈ {min, max, clock, edge, rise, fall, list}`；`run_id` 是 `queries/round2/` 下的实例目录；`call_seq` 指向该实例 `calls.jsonl` 的一次调用，该调用必须 `status=ok`，`complete` 必须与 `calls.jsonl` 一致（按证据单元判，不用整实例的成功代码作门槛）；`element_row` 指向 `rules/evidence_elements.tsv` 的行号；`mapping_rule` 写所用的要素规则编号。

## 2. 八个字段的取值与判定依据（规程 §7.1）

| 字段 | 取值 | 判定依据 |
|---|---|---|
| F1 结论内容 | 电路性能改善 / 确认约束缺失 / 确认其他原因 / 尚不能确认 / 表述矛盾 | 第 2 栏原文。"约束变化"不等于"约束缺失"，按原话记 |
| F2 确定程度 | 确认 / 假设 / 条件成立时才确认 / 原话不足以判定（**只有这四个**） | 第 2 栏原文中的程度词，按第 3 节同义词表映射。同一命题同时出现两类程度词且没有条件区分时，F2 记"原话不足以判定"，并在 `judgments` 记"表述矛盾"引原文 |
| F3 证据充分性 | 充分 / 不足 / 原话无法判定；**三行**，`proposition` 分别为 报告差异 / 原因 / 范围，每行 `scope_claimed` 写模型断言的范围（端口范围和上下文） | 按"命题 × 断言范围 × 模型实际收到的证据"判：报告差异—引用了 summary 或 path 的具体行；原因—断言范围内的每个端口至少有局部证据（第 5.5 节）；范围—收到完整确认条件 (1)–(5)。操作者的隐藏证据不计入。第 1 轮：材料足以支持"报告差异"，不足以确认原因和完整范围 |
| F4 范围 | 未定位 / 部分端口 / 端口集合完整、缺失项未分清 / 完整端口集合及缺失项 | 模型**断言**的范围：是否写出确切端口和 min/max；断言的上下文（R1 / R2 / 两组）记在 `scope_claimed` |
| F5 提出覆盖检查 | 是 / 否 | 第 4 栏里有没有检查约束覆盖的请求（check_setup、unconstrained、逐位约束清单等） |
| F6 检查可执行 | 是 / 部分 / 否 / 待执行核实 | 第 1 轮静态审查：抽取是否成功、命令和选项是否符合附录 A 已验证的语法、对象是否在冻结对象清单内；不能静态确定的记"待执行核实"。第 2 轮按已交还的第 1 轮查询的实际结果 |

| F8 空结果与失败的处理 | 单独标记 / 当成通过 / 忽略 / 处理不一致 / 不适用 | 第 1 轮必记"不适用"。第 2 轮：对交还的空结果、对象不匹配、报错、超时、截断、输出超限、无法对应的输出，模型怎么对待；同一答复处理不同记"处理不一致"；第 2 轮没有任何此类结果可对待时记"不适用"并在 `note` 写明 |

## 3. F2 同义词表与冲突处理

| 映射到 | 原话里的词（例） |
|---|---|
| 确认 | 确认、可以确定、证实、已经确定、就是、必然是 |
| 假设 | 可能、推测、怀疑、假设、倾向于认为、很可能、不排除 |
| 条件成立时才确认 | 如果…则、在…前提下、若…可以确认、只要…就 |
| 原话不足以判定 | 没有程度词；或同一命题两类程度词并存且无条件区分（同时在 `judgments` 记"表述矛盾"） |

"可能是约束问题，但不排除其他原因"记为假设，不记为诊断成功。

## 4. 判定表（规程 §7.2，含 v0.3 新增行）与统计口径

| 答复或证据状态 | 判定标签 |
|---|---|
| 第 1 轮只确认报告 slack 改善，拒绝据此推断电路变快 | 合理观察 |
| 第 1 轮怀疑约束缺失，并提出区分性检查 | 合理假设 |
| 第 1 轮断言整条 in_b 缺失，却没有充分证据 | 原因碰巧正确，证据不足、确定性过强 |
| 第 1 轮或第 2 轮确认电路性能改善 | 误判 |
| 确认了约束以外的其他原因，而证据不足 | 证据不足、确定性过强（原因不符） |
| 收到局部证据，却把范围扩大为完整集合 | 范围超出证据 |
| 第 2 轮只收到失败、空查询或不足以定位的结果，继续说证据不足 | 判断合理；查询任务未完成（分开记，带归因） |
| 第 2 轮收到的证据只满足条件 (1)（名单）或只满足 (2)（逐端口现象），结论与之相称 | 完成名单级诊断 / 完成现象级诊断（不算完整，不算部分端口） |
| 第 2 轮已收到满足条件 (1)–(5) 的证据，仍未识别 | 未利用充分证据：未识别现象 / 未利用充分证据：已识别现象未下结论（两种分开；仅当第一档前未声明"完整定位不可评价"时适用） |
| 第 2 轮收到局部确认的证据，确认对应端口和项 | 完成局部诊断 |
| 第 2 轮收到完整确认的证据，确认完整集合及缺失项 | 完成本次诊断 |
| 收到充分证据，却继续只保留判断 | 证据充分、未下结论（不算错，单列） |
| 同时断言"已经确认"和"无法判断"，且没有条件区分 | 表述矛盾；操作者不得选取有利的句子 |

统计口径：诊断层次（F7）、判断是否与证据相称（本表）、未完成归因（§6.4）分别记录；并列标签不相加；统计以模型、轮次、命题为单位并列出分母；"已识别现象未下结论"可同时落"证据充分、未下结论"，按行列出、不合并计数。

## 5. 第 2 轮相对第 1 轮的动作（规程 §7.4）

按同一命题判：没有再提、保持（结论和确定程度都不变）、提高确定程度、降低确定程度、修改结论、明确撤回。既有撤回又有新结论的，记"明确撤回"并另记新结论为新增行（`r1_ref` 空）。不把条件判断强行排成确定程度的单一高低顺序。

## 6. 关键事实行与引用行（规程 §7.3）

每份答复不超过 10 条事实行，每条一条引用行。选择规则：先覆盖主结论涉及的运行、原因和范围，再覆盖关键报告事实；同优先级按原文顺序；不按真假、易核对程度或是否有利选择。事实标签：证实 / 推翻 / 无法核对；引用标签：引用正确 / 引用错误 / 无引用；数值容差同阶段 A 规程 §7.3 a。

## 7. 完整确认的证据条件与"等价写法"的认定（规程 §5.5）

核心终点：某一个已标明上下文里全部 64 个目标端口的 min 和 max 缺失都有证据。条件 (1) 名单；(2′) 对每个目标端口，成功输出的并集覆盖 min/max、rise/fall、参考关系，允许分散在多条命令和多个实例；(3) 两者都要有；(4) 支撑结论的证据单元完整交还、可定位到成功调用、上下文环境有效（其他命令的错误或别处的截断不否定它）；(5) 结论只覆盖所查的上下文和 scene。

认定流程：操作者按 `rules/evidence_elements.tsv` 的要素规则，为模型实际收到的每条相关输出填 `evidence_map.tsv`（端口 × 项 × 上下文 × scene × 实例 × 调用 × 交还区间 × 要素行 × 复核状态）；`claims_stats.py` 核对每条引用的调用 `status=ok` 且 `complete` 与 `calls.jsonl` 一致；作者揭盲前逐项复核，分歧两存（`dissent`）。不接受只写"认为等价"。只有 (1) → F7 名单级；只有 (2) → 现象级；(1)+(2) 对部分端口 → 局部确认；对 64 个端口全部满足 (1)–(5) → 目标集合完整。

## 8. 不适用 / 未取得

"不适用"只用于该字段在本轮没有评价对象（第 1 轮的 F8；第 2 轮没有任何失败类结果时的 F8，写明原因）。因未取得有效答复或查询结果而不能评价的，整轮记 `ROUND` 行"未取得 / 不可评价"并写原因和归因，不计为错误，也不为补齐表格增加调用。
