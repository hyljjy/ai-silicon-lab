# 第 2 轮查询的抽取、执行顺序、机械改写与预算账单拼接（规程 v0.3 第 6.3、6.4 节；第一档预登记，运行后不改）

本文件把 `scripts/extract_queries.py`、`scripts/run_query.py` / `scripts/collect_runs.py`、`scripts/rewrite_query.py`、`scripts/budget.py` 和 `scripts/build_results.py` 已实现的规则写成文字登记；代码与本文不一致时以本文为准并记入版本记录。

## 1. 抽取单位（`extract_queries.py`）

1. **读取范围**：只读答复的核心窗口——从"一、观察"等四个标题中最先出现的那一行起、连续 120 行（`scoring.core_window`，与核心评分用的是同一个窗口）。窗口之外的行保留在答复文件里，但其中的检查请求**不抽取、不执行**，数量记在 `extracted_<code>.tsv` 的说明行（`outside_window`）。理由：规程第 6.3 节规定四栏合计不超过 120 行、超出部分不进入核心评分；如果窗口外的请求仍可取得第 2 轮证据，答得长的模型就能越过评分截止线多拿证据（外审 `CASE02_R6_codex.md` Q3）。本条 2026-10-29 由操作者裁定、写入本文，作者同日确认（原话："都确认"）。
2. **第四部分**：从匹配"四、检查请求"（或"四、下一步查询"）的行之后开始，到下一个以"五"开头的部分标题之前结束。
3. **一个单位**是：(a) 一个围栏代码块（```tcl 等），或 (b) 同一行里以允许命令开头的反引号内联代码（一行多个内联段合成一个单位，按顺序拼接），或 (c) 既不是代码块也不含可执行内联代码的条目正文，记为 `text` 单位（不可运行，写 `.txt`，不计入 12 条）。代码块紧跟在列表条目正文后面时，条目正文属于这个代码块的提示语，不单独成 `text` 单位。
4. **上下文作用域** `ctx_requested`：先看代码块正文（注释行不算）里出现的 `R1` / `R2`；没有就看所属条目的提示语；都没有记 `both`（R1、R2 各执行一次，分别标注）。
5. **优先级** `priority`：条目里的"优先级 n"或"第 n 优先"；没有写为空。
6. **编号**：按出现顺序 `<code>1`、`<code>2`……（`qid_numeric` 排序，不按字符串）；第 13 条起 `over_limit=1`，固定代码 `未执行：超出预登记上限`，不执行。
7. 抽取是确定性的；作者在第 2 轮前复核 `extracted_<code>.tsv`，不改动单位的内容。

## 2. 执行顺序（`run_query.py` / `collect_runs.py`）

1. 每个单位对其作用域内的每个上下文各执行一次，称为一个实例（`<qid>_R1` / `<qid>_R2`）。
2. **先原样执行**（`run_id_first`）。原样执行的输出里出现第 3 节两条触发规则之一的错误行时，按规则改写一次，在同一上下文**再执行一次**（`run_id_rewritten`）。两次运行都保留；交还给模型的是改写后那次的输出，并注明应用了哪条规则。没有触发时只有一次运行。
3. 每个实例按规程 5.2 节重建分析环境并核对记录（关系 `query_env_vs_formal`）；环境无效的实例保留失败记录，交还固定说明，归因"执行器或环境问题"。
4. 单实例上限（2000 内容行 / 256 KiB）在每个实例上分别截断；总预算在全部实例截断后按 `keep_order`（声明的优先级 → 请求编号 → R1 先于 R2）累计。

## 3. 机械改写规则（`rewrite_query.py`，只有这两条）

| 规则 | 触发条件（原样执行输出里的错误行） | 替换 |
|---|---|---|
| R2 | `CASE02-ERROR: Error 514: … '-corners' is not a known keyword or flag.` | `-corners` → `-scenes` |
| R3 | `CASE02-ERROR: invalid command name "report_timing"` | `report_timing` → `report_checks`；`-max_paths N` → `-group_path_count N`；`-nworst N` → `-endpoint_path_count N`；`-delay_type max|min` → `-path_delay max|min` |

替换只作用于完整的词（前后不是字母、数字、下划线或连字符）。没有其他改写：缺 `-scene` 的 `Error 103` 原样交还（规程 R3 Q3，作者决定），对象找不到、语法错误等也原样交还。

## 4. 翻译表与预算账单的拼接（`budget.py`、`build_results.py`）

1. `round2/<code>_results.md` 按 `qid_numeric`、R1 先于 R2 的顺序列出每个已交还实例：原始查询、实际执行的查询（改写时注明规则）、输出（截断后）、结果代码、执行结果、归因；未交还的实例只出现在账单里。
2. 账单由 `budget.statement()` 生成，固定附在 `<code>_results.md` 末尾，四项依次为：① 总预算（token，与 `context.md` 一致）；② 已交还的实例：查询编号、上下文、各占多少行、是否经单实例上限截断；③ 未交还的实例：查询编号、上下文、完整输出的行数、按哪条顺序规则被排到后面；④ 固定一句"以上未交还的结果已完整归档，未交还原因是累计超过公开的总预算，不是查询失败。"没有未交还实例时 ③ 写"（无）"。账单自身的字节也计入总预算（分配时求不动点）。
3. `build_prompt.py round2 <code>` 在写出题目前做两项核验：结果部分 ≤ 总预算；整份第 2 轮题目 ≤ 预算推导里为它预留的容量（`budget.prompt_capacity`），结果写在 `round2/<code>_rendered_check.json`，不通过就不写题目。
4. 模型看到的 `<code>_results.md` 和第 2 轮题目里不出现版本名、分配、模型名（`label_check` 在发送前检查发送的字节）。
