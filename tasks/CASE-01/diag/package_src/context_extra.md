
## 分析条件（只说明条件和限制，不含对任何路径的分析）

- 分析对象：上面接口描述的 `dot4sat` 模块经综合得到的门级网表。这是基线实现：只在输出端寄存，延迟 L = 1。延迟 L 的定义见合同第 2.2 节：第 n 个上升沿采样到的交易，在第 n+L−1 个上升沿打入输出寄存器；L = 1 时，输入经组合逻辑，在采样它的那个上升沿打入输出寄存器。
- 分析工具：OpenSTA 3.1.0。这个版本用 scene（场景）组织 corner：`report_checks`、`find_timing_paths` 用 `-scenes` 选择场景（缩写 `-scene` 也可以用）；`report_wns`、`report_tns`、`report_worst_slack` 没有选择场景的选项。
- 分析模型：综合后分析；理想时钟（时钟延迟、uncertainty、transition 都为 0）；不读取寄生参数，连线负载只计引脚电容。
- 工艺库：Sky130 HD（`sky130_fd_sc_hd`），共 6 个 PVT 点：`tt_025C_1v80`、`tt_100C_1v80`、`ss_100C_1v60`、`ss_n40C_1v60`、`ff_n40C_1v95`、`ff_100C_1v95`。
- 输入约束：数据和控制输入（`in_a`、`in_b`、`in_valid`、`rst`）由 `sky130_fd_sc_hd__buf_2`（A→X）驱动，输入 transition 为 0；输入延迟 max 为 0.2T，min 为 0。
- 输出约束：输出延迟 max 为 0.2T，min 为 0；输出负载为 C_load。约束原文见 `case01_sdc.tcl`，取值见 `values.txt`。
- 综合配方：固定的专用 Yosys/ABC 命令序列，没有时钟目标和 IO 目标，不包含物理层面的时序修复。
- 综合网表存在，但没有提供给你。你可以在"下一步查询"中提出针对网表的 OpenSTA 查询。
- `path_report.rpt` 是下面这条命令的输出，内容是 `ss_n40C_1v60` 下"输入到寄存器"这一类的 setup 路径。按默认设置，`report_checks` 只报告 slack 最差的一条：
  `report_checks -from [all_inputs -no_clocks] -to [all_registers -data_pins] -path_delay max -scene ss_n40C_1v60 -fields {slew cap input_pins fanout} -digits 4`
- 时钟周期 T 的来历：T 是按"基线最差 setup slack 约为周期的 −15%"校准得到的固定值。修改建议不得改变 T 或任何约束；查询中可以提出改变周期或约束的对照分析，其结果只作对照。
- 修改建议必须满足的限制：延迟 L 不超过 3；每个时钟周期都能接收一笔新交易；接口和 IO 约束不变；面积不超过基线的 1.25 倍。
